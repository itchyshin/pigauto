The GNN campaign is CPU-oriented. Use Totoro after a live capacity check; use DRAC arrays if Totoro lacks safe headroom. Kohaku's GPU is not assumed available to R torch and will be considered only after a supported CUDA smoke and CPU-parity check. Both `phylo_signal_gate` settings are included by user selection; `FALSE` is the shipped default and confirmatory policy, while `TRUE` is the policy-sensitivity arm.

The first 25-dataset Totoro attempt failed because the campaign's quadratic covariate-basis matrix had the wrong shape; its failed and interrupted attempts are retained as invalid evidence. The helper is fixed with a regression check. A DRAC CPU environment was provisioned while Totoro capacity was uncertain; its queued job was cancelled before start, so no simulation ran there. Totoro's subsequent live load check supported the corrected pilot on Totoro.

The launched pilot requests five datasets, one per scenario, with both gate policies (10 fits), 2,000 maximum epochs, and four workers. Production runtime is unresolved until those results arrive. If production is estimated above three hours, stop at the pilot and request approval before production. The pkgdown article remains deferred while the active validation lane owns it.
